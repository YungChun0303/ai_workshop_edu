## 1. Project Overview

- **Title:** Neighborhood redevelopment, residential sorting, and student achievement in St. Louis
- **Principal investigator:** Workshop demonstration (CERP³, Washington University in St. Louis)
- **Research question:** Did the Choice Neighborhoods Initiative (CNI), which began in 2019 in ZIP 63106 and five nearby schools, (a) change who lives in the neighborhood, and (b) improve test scores for students who entered CNI schools or moved into the neighborhood?
- **Design:** To be decided. The empirical strategy is proposed in step 03 and recorded in `writing/analysis_plan.md` once the researcher approves it. Until then, do not estimate any causal model.
- **Unit of analysis:** Student-year (state education records); ZIP-year (Census ACS-style estimates).
- **Data source(s):** Synthetic state education records 2012–2023 (core, MAP tests, enrollment, discipline, school lists) and a synthetic ACS ZIP panel 2014–2023. Codebook: `data_raw/codebook.md`.
- **IRB protocol:** Not human subjects research (fully synthetic data).
- **Target output:** A brief for drafting the Methods and Results sections of a journal article.

## 3. Script Naming (4-Digit Rule)

All scripts in `code/` are R Markdown (`.Rmd`) and numbered by stage:

| Range | Stage | Reads from | Writes to |
|---|---|---|---|
| `0000–0999` | Import | `data_raw/` | memory / `data_clean/` |
| `1000–1999` | Cleaning & transformation | `data_raw/`, `data_clean/` | `data_clean/` |
| `2000–2999` | Descriptive statistics & EDA | `data_clean/` | `outputs/` |
| `3000+` | Main models | `data_clean/` | `outputs/` |

- Leave gaps so new steps fit without renumbering (e.g., `1100_zip_panel.Rmd` after `1000_clean.Rmd`).
- Names are lowercase `snake_case`: `1000_clean_student_panel.Rmd`, not `Clean Data FINAL v2.Rmd`.
- Each script should run top-to-bottom on its own, given the outputs of earlier-numbered scripts.

## 4. R Conventions

- **Paths:** always build paths with `here::here()`, e.g., `here::here("data_raw", "dese_student_core.csv")`. The project root is marked by `part3_live_workflow.Rproj`. Never hard-code absolute paths.
- **Packages:** load all packages in the first (setup) chunk. Preferred: `tidyverse` for data handling, `fixest` for fixed-effects regressions, `did` for staggered difference-in-differences, `tidysynth` for synthetic control, `knitr::kable()` for tables. Ask before installing anything else.
- **Reading CSVs:** read ZIP code columns (`zipcode`, `SCHZIP`) as character.
- **Saved data:** write cleaned data as `.rds` (`readr::write_rds()`), not `.RData`.
- **Seeds:** set `set.seed(20261016)` once in the setup chunk of any script with randomness.
- **Chunk visibility:**
  - Silent file operations: ```` ```{r, include = FALSE} ````
  - Code shown, console noise hidden: ```` ```{r, echo = TRUE, results = 'hide', message = FALSE, warning = FALSE} ````
  - Aggregate result tables may be shown with ```` ```{r, echo = TRUE, message = FALSE, warning = FALSE} ````
- After writing or editing a script, **knit it and fix errors before reporting back.** Report what ran, what failed, and what you changed.

## 5. Data Security

- **Data classification for this project:** Synthetic (no real persons). In a real project with these files, the classification would be FERPA-protected student records.
- If a project contains **PHI, stop: do not use Claude Code on it.** (At WashU, PHI is approved only in Claude Secure, which does not include Claude Code.)
- **Never print individual-level records** to the console or into documents, even here — practice the habit. Use `glimpse()`, `summary()`, counts, and aggregates instead of `head()` / `View()` on student data.
- Suppress or flag any table cell with fewer than 10 students.
- Never write credentials, API keys, or passwords into any file.
- Workshop exception: the synthetic `data_raw/` files are published with the repository. In a real project, never commit `data_raw/` or `data_clean/`.

## 7. Writing Guidelines

- Objective, academic prose. No promotional language.
- Avoid: "delve," "testament," "tapestry," "moreover," "foster," "it is important to note."
- No conversational filler ("Here is your code:", "Great question!").
- **Every number in a draft must come from a file in `outputs/`.** Name the source file in an HTML comment next to it, e.g., `<!-- source: outputs/tables/3000_main_estimates.csv -->`.
- **Never invent citations.** If a claim needs a reference, write `[CITATION NEEDED]` and leave it for the researcher.
- Markdown files: no hard line wraps inside paragraphs.
